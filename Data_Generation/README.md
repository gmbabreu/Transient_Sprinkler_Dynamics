# Laser Sprinkler Angular Displacement Analysis

MATLAB scripts extract angular displacement from `.MTS` recordings by tracking
a laser dot, converting its pixel position to calibrated ruler coordinates,
and converting those coordinates to sprinkler angles.

## Paths and directory layout

The active scripts resolve all input and output paths relative to their own
location, independently of MATLAB's current folder. Calibration scripts,
helpers, reference images, and generated calibration files live together in
`Data_Generation/calibration`.
Keep the following layout when moving the project to another computer:

```text
Data_Generation/
├── save_frames.m
├── generateData.m
├── plotData.m
├── ycbcrMask.m
├── calibration/
│   ├── calibrateRulerAxis.m           # Interactive ruler calibration
│   ├── calibrateSpring.m             # Spring stiffness calibration
│   ├── projectToRulerAxis.m          # Ruler projection helper
│   ├── frame.jpg                     # First frame of the batch's first video
│   └── frame_rulerCalibration.mat    # Generated by calibrateRulerAxis.m
├── trials/
│   └── 1000r1.MTS                    # Supplied recording (example trial)
├── frames/
│   └── 1000r1_frames/                # Generated by save_frames.m
│       ├── 001.jpg
│       ├── 002.jpg
│       └── ...
└── data/
    ├── 1000r1_data.csv               # Generated by generateData.m
    ├── 1000r1_maskedData.mp4         # Optional masked video
    ├── 1000r1_overlayData.mp4        # Optional tracking overlay video
    ├── 1000r1_overlayFrames/         # Optional individual overlay images
    └── 1000r_meanData.csv            # Generated by plotData.m
```

Recordings, extracted frames, and calibration results must be supplied or
generated before processing; resolving paths does not create those inputs.
The scripts create frame and diagnostic output folders as needed.
The root `.gitignore` excludes video files under `Data_Generation` and extracted
images under `frames/` by extension. The folders themselves and other file types
are not ignored. Git does not track empty folders: create `trials/` locally for
your recordings; `save_frames.m` creates the required frame folders.

## Running the pipeline

1. Place recordings in `Data_Generation/trials/` using the naming convention
   `{Re}{direction}{trial}.MTS`, where direction is `f` or `r`.
2. Set matching trial selections in `save_frames.m` and `generateData.m`.
   Their current defaults differ, so adjust both before processing a trial.
   Run `save_frames.m` to extract JPEGs into `frames/{trialName}_frames/`.
   Each run also replaces `calibration/frame.jpg` with the first frame of the
   first video in the `trials` list, even if its trial number is not 1. Later
   videos in the batch leave this reference image unchanged. The same frame
   is also saved as `001.jpg` in that video's extracted frame folder.
3. Run `calibration/calibrateRulerAxis.m` and click the specified ruler marks
   on `calibration/frame.jpg`. It saves `calibration/frame_rulerCalibration.mat`,
   which `generateData.m` loads. Repeat calibration when the camera/ruler setup
   changes. Run `calibration/calibrateSpring.m` when recalibrating the spring;
   it prints the stiffness to use for `kappa` in `main.py`.
   Updating `frame.jpg` does not refit the saved ruler calibration; rerun the
   ruler calibration script when a new batch needs a new calibration.
4. Run `generateData.m` to write `data/{trialName}_data.csv` with headers
   `time_seconds,angle_degrees`. Frame 1 is timestamped at zero.
5. Optionally set the matching trial prefix and count in `plotData.m`, then
   run it to align trials, plot their mean, and save `data/{prefix}_meanData.csv`.
6. For torque reconstruction, select the trial in the repository's `main.py`
   and run it with Python. It reads the per-trial CSV from this same `data/`
   directory by default.

To invoke these scripts from another MATLAB folder, add `Data_Generation` and
`Data_Generation/calibration` to the MATLAB search path and call the script by
name. `generateData.m` also adds the calibration folder to the search path
automatically so it can find `projectToRulerAxis`.

## Processing details

`generateData.m` applies `ycbcrMask` to each frame and computes the laser's
weighted centroid. `projectToRulerAxis` maps that centroid to inches using
the saved ruler calibration. Angular displacement is measured relative to
the first detected laser position, using the configured mirror distance `D`.

Enable `maskedVideo`, `overlayVideo`, or `overlayFrame` to save diagnostics
under `data/`. Existing per-trial CSVs require confirmation before replacement.

`plotData.m` detects motion using the absolute angular velocity and the
configured `motionThreshold`. It aligns trials to the earliest detected onset,
interpolates them onto a shared time grid, and averages samples valid in every
trial. These aligned mean timestamps differ from original recording times;
use the per-trial CSVs for comparisons with audio cues in original seconds.

`ycbcrMask.m` uses YCbCr thresholds to isolate the laser. Adjust these thresholds
for the recording conditions when necessary. MATLAB's Image Processing Toolbox
is required for the image-processing workflow.

The scripts in `Archive/` retain their older path conventions.
